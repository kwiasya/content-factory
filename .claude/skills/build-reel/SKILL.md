# Build the Reel in Resolve

API rules: `docs/resolve-rules.md`. Color pipeline: `docs/research/03-color-iphone-osmo/result-a.md` Section B. Overlay path: `docs/research/02-overlays-and-motion-graphics/result-a.md` Section C. Style and safe zone: `style.json`.

## Steps

1. Preconditions: Resolve open; `script.json` validates; `cuts.json` exists (without a Track, derive `cuts.json` from the Script's `in_s`/`out_s` directly and say so); when the Script has Asset cues (`shots[].assets`), the Library is indexed (`/index-pack`) and the validator passes with it.
2. Overlays first, while Resolve is idle: `.venv/bin/python -m cf.build reels/<reel>/ --overlay-specs` writes one spec per shot overlay, `overlays/specs/<shot>.json` (length = its spanned shots; the overlay's `preset`, `anchor` and `in_frames`/`out_frames` from the Script; no Resolve), and prints one `node overlays/render.mjs --spec … --out reels/<reel>/overlays/<shot>.mov` per overlay; run them one at a time →  `reels/<reel>/overlays/<shot>.mov` (ProRes 4444, alpha, canvas from style.json, 2160×3840 by default, timeline fps, concurrency 2; the design is laid out in the 1080-wide reference space and scaled ×2, about 11–13 s and 1.8 GB per overlay at 4K). Skip when the overlay file is newer than `script.json` and was rendered with the same `font_ref`.
   Font: first run `.venv/bin/python -m cf.assets font reels/<reel>/script.json` once. It prints `{"ref", "path", "source"}` (the Format's `- Overlay font: `@font/<name>`` line, else `style.json` `typography.font`) or `{"ref": null}`. Put `font_file` (the path) and `font_ref` into every overlay spec before rendering it, and keep the last `font_ref` in `reels/<reel>/overlays/font.json` (`{"font_ref": …}`) so a font change re-renders every overlay. A broken ref exits 1 with the nearest matches: stop and show them to the Author. The render summary's `font` names the file used.
3. Run `.venv/bin/python -m cf.build reels/<reel>/` which, through `resolve_driver`: creates or reuses project `cf-<footage>-<reel>` from the project settings preset (color managed v2, DWG/Intermediate, HDR 1000 working luminance with inverse DRT, Rec.709 Gamma 2.4 out, canvas from style.json, 2160×3840 by default, 30 fps; `--canvas 1080x1920` for a comparison build); imports the clips and overlays (an HDR clip, iPhone HLG / Dolby Vision, as its Apple SDR mezzanine `<footage>/mezz/<stem>.mov`, made or reused by `cf.mezz` / `tools/apple-sdr` before Resolve is touched: Apple's own tone mapping, what the author sees in QuickTime and Photos, `docs/adr/0011-hdr-clips-through-apple-tone-mapping.md`; SDR clips from `raw/` as they are); forces each clip's `Input Color Space` to the manifest value (`Rec.709 Gamma 2.4` for a mezzanine); sets Super Scale 2x on clips whose display height is below the canvas (the 1080p iPhone clips on 4K; `style.json` `upscale`, `--no-superscale` turns it off) and 1 on the rest; deletes any existing timeline of this name and appends V1 shots, V2/V3 overlays (a re-rendered overlay is swapped in with `ReplaceClip`) and A1 ambience by `record_frame` (from `cuts.json` when present, otherwise back to back with each shot snapped down to whole frames); with `script.track`, the Track on A2 "music" from frame 0 for the picture's length, source in-point `track_in_s` (default `intro_end` from `beats.json`), 0 dB, `track_fade_out_s` fade (0.6 s); applies speed, transitions, fades; `AudioVolume` −20 dB (`style.audio.ambience_db`) on ambience under a Track, 0 dB without one (`--ambience-db` overrides); `--no-track` builds the same cut without the Track for a sound added in Instagram; then, only for HLG clips imported as HLG (`--hdr-source resolve`), the HLG exposure CDL on node 1 (`docs/research/color-hlg-experiment.md`); then the Look LUT from `style.json` `look.lut` (null since 2026-10-12: the author's rule is original colour, as on the Mac, so no Look unless she asks for one with `--look <file.cube>`) on node 1 of the `cf-look` color group's post-clip graph, with every V1 item in the group (`docs/research/look-experiment.md`; `--stills-only` re-exports stills with a different Look without rebuilding); shot markers (role colors, shot id in `customData`) and `cuts.json` `beat_markers` (downbeats Blue, other beats Cyan). Delivery: `--deliver hdr-hlg` builds for an HDR render (`cf.render --hdr`): output `Rec.2020 HLG ARIB STD-B67`, no HLG CDL, no Look unless `--look` names one, and the overlays converted to HLG at graphics white (203 nits, `--overlay-nits`) into `reels/<reel>/overlays/hlg/` (`cf.hdr`, cached by a sidecar JSON); the default `sdr` is unchanged. `--hdr-source resolve` imports HLG clips as HLG and lets Resolve convert them (one stop brighter and flatter than the Mac shows them); `--hlg-normalize none` (SDR, with `resolve`) leaves the −1.02 stop CDL off: Resolve's own HLG → 709 conversion, about 30 luma levels brighter, with 10–20 % of pixels ≥ 235 (`docs/research/hdr-hlg-delivery.md`). Rebuild to switch: the render refuses a timeline whose output does not match its mode. A reel the author graded by hand (the reel folder's `author-grade` folder, see its `grade.json`) must be rebuilt with `--grade-drx <reel_dir>/author-grade/` and the build options listed there, or her grade is lost.
   Landscape clips on the vertical canvas are reframed per shot `reframe` (default `follow` from `style.json` `reframe.default`; `cf.reframe`, `cf.follow`): before Resolve is touched, the person detector on the proxy places one static 9:16 window per `follow` shot (the loop-seam pair shares one), then fit-height `ZoomX`/`ZoomY` and `Pan`; the report's coverage table gives x, % of frames holding the whole person, and the black band per still. Any still with more than 8 px of black at an edge fails the build (author: no black bars). `smart` (Smart Reframe) is opt-in only: it tilts past the frame edge.
   Canvas: `--canvas` (preset name or WxH) > the Script's `canvas` (`landscape` = 3840×2160, 16:9) > `style.json` `canvas`; on `landscape` render overlays with `"canvas": "landscape"` in the spec (or `render.mjs --canvas landscape`) so they get the 16:9 safe zone and positions, and 16:9 clips are not reframed.
   Asset cues (`docs/script-schema.md` Assets): sound effects on A3 "sfx" (A4 when two overlap) at 6 LU under the Track's measured loudness over the part used (under −14 LUFS without a Track), plus the cue's `db`, capped by the true peak; pictures on V4 "assets" (V5) from the Pack's ProRes alpha variant, the keyed or converted cache file or the png, scaled to fit the `pos` box (ZoomX ganged, Pan, Tilt); a meme's own sound on an A lane at the same rule. The Library is loaded read-only from the Video's root (`--shared-root`, `--db` for another); validation warnings (unknown rights allowed) go into the report notes. `--no-assets` builds the same cut without the cues. The Pack is only read.
4. Read-back report: the driver prints each shot's expected vs actual start/end, every property it set, every mismatch. A mismatch is a failure; fix the driver or the plan, then rebuild.
5. Export one still per shot (`ExportCurrentFrameAsStill`, at the canvas size) into `reels/<reel>/stills/` and look at them (the luma check runs on the still downscaled to the proxy size; for a mezzanine shot the reference is the mezzanine frame and a difference over 3 levels is a mismatch): overlay inside the safe zone, colour as the source on the Mac. Each picture cue also gets `stills/cue-<cue>.png` at its middle frame: check the sticker or meme sits where `pos` says, with its transparency, clear of the overlay text.
6. Tell the user the timeline is ready for review in Resolve and which shots to check first.

Done when the read-back report has zero mismatches and the stills have been checked.
