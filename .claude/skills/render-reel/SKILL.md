# Render and verify

Export settings and their reasons: `docs/research/03-color-iphone-osmo/result-a.md` Section D. Loudness: `docs/research/05-music-and-sound/result-a.md` Table C.

## Steps

1. Ask the user to confirm edits in Resolve are done; the render reads the timeline as it is now, including their changes.
2. Run `.venv/bin/python -m cf.render <footage>/reels/<reel>/` (`--footage`, `--out`, `--preset` optional). It opens project `cf-<footage>-<reel>` (it never creates one) and timeline `<reel>`. It creates or updates render preset `cf-instagram-<w>x<h>` from style.json: canvas from style.json, 2160×3840 by default, 30 fps, `render.codec` (H.264 High), `render.bitrate_mbps` for that size (45 Mbit/s at 4K, 22 at 1080×1920), AAC 48 kHz, `ColorSpaceTag` Rec.709, `GammaTag` Rec.709-A. `--canvas 1080x1920` makes a comparison render at that size, deletes this timeline's old jobs, queues one job and polls `GetRenderJobStatus` until done → `out/<reel>.mp4`. Then it restores the UI page and writes `out/render-report.json`. An `--out` named `<reel>.<x>.mp4` writes `render-report.<x>.json` and `render-check.<x>.json`, so a variant never overwrites the published reports. `--hdr` (timeline built with `cf.build --deliver hdr-hlg`) renders Rec.2100 HLG instead: preset `cf-instagram-<w>x<h>-hlg`, H.265 Main10, `ColorSpaceTag` Rec.2020, `GammaTag` Rec.2100 HLG, same bit rate; the check then expects hevc Main 10 `hvc1`, `yuv420p10le`, bt2020 / arib-std-b67 / bt2020nc (`cf.render_check --hdr`). `--target-tp` sets the true-peak ceiling for the check and the loudness fix (music reels: −3). Upload an HDR file from the iPhone's Photos app (AirDrop it there first), so Instagram keeps HDR.
   The canvas follows the same rule as the build: `--canvas` > the Script's `canvas` (`landscape` → 3840×2160, preset `cf-instagram-3840x2160`, 45 Mbit/s) > `style.json` `canvas`; `cf.render_check` on a file in `<reel>/out/` reads the Script's `canvas` too.
3. The same command then runs `python -m cf.render_check out/<reel>.mp4`. It checks with ffprobe: `bt709/bt709/bt709`, `color_range=tv`, `yuv420p`, the canvas size from style.json (2160×3840 by default; `--canvas` on `cf.render_check` for another size), 30 fps, no DOVI side data, AAC 48 kHz, and duration = timeline length. It measures loudness with ffmpeg `loudnorm` print mode (target −14 LUFS ±1, true peak ≤ −1 dBTP), prints a PASS/FAIL table, writes `out/render-check.json`, and exits non-zero on FAIL.
4. If only loudness fails, re-run with `--fix-loudness` (on `cf.render`, or on `cf.render_check <file>` to skip the re-render). It writes `out/<reel>.normalized.mp4`: two-pass `loudnorm` with the video stream copied, repeated on its own output (at most 3 rounds) when loudnorm falls back to dynamic mode. Then it re-checks that file. Upload the `.normalized.mp4` when it exists.
5. Report the file path, duration, size, render time and the verification table. On the earlier MacBook Air M2 8 GB, a 16 s Reel at 4K rendered in about 47 s with Super Scale 2x on the 1080p clips (27 s without it, 10 s at 1080×1920) and was about 91 MB; expect it faster on the current M5 Max, not yet measured.

6. Publish for the author: set `title` in `script.json` if missing (place — what the video is, in Russian, e.g. "Майорка — отель и пляж"), then run `.venv/bin/python -m cf.publish <footage>/reels/<reel>/`. It puts two files per reel in `~/Movies/Готовые ролики/`, side by side: the video (the no-music render when there is one, because the author adds the sound in Instagram) and `<title> — подпись к посту.txt`. Nothing else goes in that folder. Tell the author the file name, not the internal path. To publish a variant render instead of `out/<reel>.normalized.mp4`, pass `--variant <x>` (e.g. `hdr` → `out/<reel>.hdr.normalized.mp4`; the no-music file is `<reel>.ambience.<x>…` when it exists, else the default one with a note).

Done when the verification table passes on the file in `out/` that will be uploaded.
