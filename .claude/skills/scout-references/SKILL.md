# Scout References

Turns a Watchlist into a fresh feed of Reference ranked by Outlier score (`GLOSSARY.md`, section Исследование): views from the latest snapshot ÷ the median of the same channel's last 30 videos of the same kind (short ≤ 180 s, long otherwise) that are at least 3 days old. No score (`—`) means the channel has fewer than 5 such videos yet. Instagram reels are short and score against their own account only; a reel without views scores by likes (`по лайкам` in the feed). CLI: `.venv/bin/python -m cf.research scout|snapshot|feed --help`. Calls need `YOUTUBE_API_KEY`: exported, or in `.env` in the repo root (gitignored, see `.env.example`). Quota: uploads and snapshots cost 1 unit of 10 000 a day per call (50 videos per call); every search page costs 1 of 100 search calls a day. Instagram (ADR 0007): Business Discovery, one call per page of 50 media from the hourly `instagram` bucket (100 calls in any 60 minutes; Meta's own usage headers pause it from 90 %); needs `INSTAGRAM_ACCESS_TOKEN` and `INSTAGRAM_USER_ID`. A Watchlist with Instagram accounts and no YouTube key scouts Instagram and says the YouTube part was skipped. Check both with `.venv/bin/python -m cf.research quota`.

## Steps

1. Read `author/how-you-work.md`. If `author/` is missing or that file's headings are empty, `/author-setup` has not run yet: run it for that part (Phase 3, how-you-work), then continue.
2. Pick the Watchlist: the one the author named, else `.venv/bin/python -m cf.research watchlist list` and ask. If none exists, stop and point to `/research-watchlist`.
3. Scout: `.venv/bin/python -m cf.research scout <name> --json`. The first run per channel pages its uploads until 30 videos of each kind are known (or the history ends); later runs read new uploads, paging until they reach the newest upload of the last unbroken run (a video already known from a search hit or a fetch does not end the paging, and a run cut short by the quota or an error is completed by the next one). Search reads one page of 50 per query from the last 30 days (`--search-days`, `--search-pages`, `--duration short` for Reels-length searches, `--no-search` when the search bucket is short). A refusal before the start (exit 1, `quota:` line) means nothing was spent: report it with the reset time (midnight Pacific) and stop. A non-null `stopped` means the quota ran out midway: what was read is kept, a later run resumes; say so and go on to the feed. A channel or query with a non-null `error` (a deleted or private channel, a rejected filter) was skipped and the rest of the run went on; the human output has one `Ошибка …` line per failure. Report each in one line (a dead Reference channel is a candidate for `watchlist remove-channel`). Exit 1 with every channel and query failed means nothing was read: report the errors and stop. Instagram channels backfill up to 50 reels on the first run (at most 3 pages), then read new reels only. The human output ends with the Instagram token's days left; a `ВНИМАНИЕ, токен Instagram` line (fewer than 7 days, or invalid) goes to the author at once with the fix: `.venv/bin/python -m cf.research ig token-refresh` (check with `ig token-status`; neither prints the token).
4. Snapshot: `.venv/bin/python -m cf.research snapshot <name> --json`. One row per Reference per run; history is kept, so running it daily builds velocity data. Instagram: the newest page (two when needed for the last 30 days) of every Instagram channel and of the owners of the author's picked reels. Mention `missing` videos (deleted or private) and `errors` (Instagram accounts that failed) in one line each.
5. Show the feed: `.venv/bin/python -m cf.research feed <name>` with the author's filters (`--days`, default 30; `--min-outlier`; `--min-views`; `--kind short|long`; `--platform youtube|instagram`; `--max-duration 60` for Walk Reel work, which drops Instagram reels because the API gives no length; `--limit`, default 20). Paste its report lines as they are: number, Outlier score, views, date, title (an Instagram reel's caption, first line), handle, link (the permalink), `по лайкам`, `без разбора` when the card has no analysis yet (not fetched, or fetched and only measured), `кандидат` when the video came from a search on a channel outside the Watchlist, `от автора` for a reel the author picked (shown whatever its age; `владелец неизвестен` when it is unresolved), `Instagram`. Read the author's Notes on picked reels (`notes list --kind card --key <shortcode>`) before you talk about them.
6. Next step, in a short list after the feed: the outliers marked `без разбора` (score ≥ 2, or the top 5 if fewer qualify), each with its link, for `/analyze-reference`; and the candidate channels from the scout output with the most hits, for `.venv/bin/python -m cf.research watchlist add-channel <name> <handle>` if the author wants them as Reference channels.

An Instagram outlier is analysed like any other: `fetch <permalink>` (media through yt-dlp without login when Instagram allows it, else a caption-only card), then `/analyze-reference`.

Done when the scout and snapshot ran (or the quota stop is reported), and the author has seen the feed and the list of outliers without analysis.
