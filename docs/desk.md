# Desk

Desk is the Author's window over the files the Editor works with (ADR 0005, `GLOSSARY.md`: Desk). It reads and writes the same files in the repo; it has no database of its own except the `note` table and the Library's Author fields in `factory.db`, launches nothing but `open -R` for "Show in Finder" (ADR 0007) and never commits. Code: `src/cf/desk/` (API), `web/` (frontend).

## Start

```sh
uv pip install --python .venv/bin/python -e '.[desk]'   # once: fastapi, uvicorn, httpx2
npm --prefix web install                 # once
npm --prefix web run build               # after every frontend change
.venv/bin/python -m cf.desk              # http://127.0.0.1:8765/
```

`python -m cf.desk` works without the frontend built: the API answers under `/api/` and `/` shows a page that says to run the build.

## Flags

| Flag | Default | Meaning |
|---|---|---|
| `--repo PATH` | current directory | Checkout to serve. The Agent page (`#/agent`) shows its path and branch, so a worktree is never mistaken for the main checkout. |
| `--host HOST` | `127.0.0.1` | Bind address. Anything other than `127.0.0.1`, `localhost` or `::1` needs `--token`. |
| `--port PORT` | `8765` | Port. |
| `--token T` | none | Shared token. When set, every request must carry it. |

Footage root and `factory.db` follow `cf.research`: `CF_FOOTAGE_ROOT` (default `~/Movies/content-factory`) and `CF_FACTORY_DB` (default `<footage root>/factory.db`). Desk reports them in `/api/meta` and opens the database for Notes and the research contour, one connection per request (`src/cf/desk/storeuse.py`). Reads open it read-only and never create, migrate or seed it: with no `factory.db` the Notes list is empty and every contour read is 404 naming the path; a database at another schema version is 409 until a `python -m cf.research` command migrates it. Writes (a Note, an Idea move or note, a taxonomy verdict) create and migrate it when needed but never load the taxonomy seed.

## Security

- By default Desk listens on localhost only and needs no login.
- To open it from a phone on the home network, start it with `--host 0.0.0.0 --token <random>` and open `http://<mac>.local:8765/?token=<random>` once; the browser keeps the token in an HttpOnly cookie. API clients send `Authorization: Bearer <random>`. Requests without the token get 401.
- Traffic is plain HTTP. Run it on a trusted network only, never on a public one and never behind a port forward.
- Desk reads and writes only paths from its catalogue (below); any other path, `..` traversal or a symlink out of the repo is 404.

## Catalogue

The groups live in one place, `GROUPS` in `src/cf/desk/catalog.py`; a new group is one more entry (id, title, globs, editable flag, title rule, empty-state hint). Kind is `json` for `.json`, otherwise `markdown`.

| Group | Files | Editable |
|---|---|---|
| `skills` | `.md` and `.json` under `.claude/skills/*/` except `remotion-*` | yes |
| `skills-vendored` | `.md` and `.json` under `.claude/skills/remotion-*/`, hidden unless `?all=1` | no |
| `content` | `CLAUDE.md`, `docs/agents/*.md`, `style.json`, `research/templates/*.md`, `research/taxonomy.json`, `author/*.md` (empty state "run /author-setup" when `author/` is missing) | yes |
| `formats` | `formats/*/FORMAT.md` editable, `formats/*/hook-library.md` read-only (generated by `hooks export`) | partly |
| `research` | `docs/research/SYNTHESIS*.md` and `NN-*/rules.md` editable; `docs/research/README.md`, the answers `NN-*/*.md` (`chatgpt.md`, `result-a.md`, `verification.md`) and `NN-*/notes/*.md` read-only; `docs/research/prompts/` is not catalogued at all | partly |

## API

| Endpoint | Returns |
|---|---|

| `GET /api/catalog[?all=1]` | groups with `docs` (`path`, `title`, `kind`, `editable`, `git`; skill files also `description` from the SKILL.md frontmatter, null for other files, `size` and `mtime`, shown in the Agent catalogue tooltip and on the skill page) and `empty` hints |
| `GET /api/doc?path=` | the entry plus `text` and `hash` (`sha256:<hex>` of the bytes on disk) |
| `PUT /api/doc` | body `{path, text, hash}`: writes atomically (temp file + rename) when `hash` matches the file; 409 with the fresh `text` and `hash` when the file changed since it was read; 403 for read-only; 422 for invalid JSON in a `json` document |
| `GET /api/doc/diff?path=` | `git` state and unified `diff` against HEAD (untracked and ignored files diff against empty) |

| `GET /api/skills/lint` | `skills`: broken reference count per own skill, for the catalogue badge |
| `GET /api/skills/{name}/lint` | `missing_paths` and `missing_skills` (`ref`, `file`, `line`) for one own skill; 404 for vendored or unknown skills |
| `GET /api/notes[?kind=&key=&all=1]` | `notes`: open Notes (all with `all=1`), oldest first, optionally of one `kind` and `key` |
| `POST /api/notes` | body `{kind, key, text}`: 201 with the Note; 422 for an unknown kind, a missing key or empty text |
| `POST /api/notes/{id}/resolve` | the Note with `resolved_at` set; 404 for an unknown id |
| `DELETE /api/notes/{id}` | the deleted Note; 404 for an unknown id |
| `GET /api/research` | `topics` from the folders `docs/research/NN-slug/` (`id`, `number`, `slug`, `title` and `status` from the README table, flags `chatgpt`, `result_a`, `rules`, `verification`, `notes` paths, `docs` paths), `synthesis` paths, `readme` path |
| `GET /api/search?q=[&all=1]` | case-insensitive substring search over every catalogued document (hidden groups only with `all=1`): `groups` of `hits` (`path`, `title`, `count` of matching lines, up to 3 `snippets` with `line` and `text`), `total`, `truncated` after 200 hits; 422 for a blank query |
| `GET /api/skills/links` | for every own skill: `paths` it mentions that exist in the repo (`catalogued` is the subset Desk can open), `commands` (`cf.research <group> [<cmd>]`), store `tables` (names from `CREATE TABLE` in `src/cf/research/store.py`, counted when written as `` `name` ``, `name table`, `name row(s)` or after `FROM`/`JOIN`/`INTO`/`UPDATE`), `skills` (folders under `.claude/skills/` mentioned as above) and `mentioned_by` |
| `GET /api/skills/{name}/links` | the same entry for one own skill; 404 for a vendored or unknown one |

Every error body is `{detail, code, params}` (`src/cf/desk/problems.py`): `detail` is English for the CLI and logs, `code` is stable and `params` carries what the message names (path, id, command). A body that does not match the request shape is 422 `request_invalid` with the `fields`. The frontend translates by `code` and falls back to `detail`. Other English sentences the UI shows carry a code too: the catalogue empty hint (`code`), a Video list entry with a broken `video.json` (`error_code`), the summary weight (`weight_code`). Script violations from `cf.script_schema` stay English.

One module, `src/cf/desk/skills.py`, defines skills for the catalogue, lint and link map: a vendored skill is a folder named `remotion-*` (catalogue entries of skill files carry `skill` and `vendored`, which the frontend reads instead of re-deriving the rule); an own skill is a folder under `.claude/skills/` with a `SKILL.md`, a lowercase name and not vendored; a skill mention is `/name` (not a Claude Code built-in command), or a known skill name right after a backtick or as `.claude/skills/name`.

Skill lint reads every `.md` of the skill. A path is a token with `/` or ending in `.md`, `.json`, `.py`, without placeholders (`<>{}*$~:`) or `..`, whose first segment exists at the repo root, the skill folder or the file's folder; it is broken when it exists in none of those. A skill mention (as above) is broken when `.claude/skills/<name>/` does not exist; only the `/name` form can name an unknown skill.

Git is read-only: status, diff, log. Commits stay with the Author or the Editor.

Search and the link map read the files on every request; there is no index or cache.

## Notes

A Note is the Author's remark on one entity for the Editor (`GLOSSARY.md`: Note), the only channel from Desk to the Editor (ADR 0005). Table `note` in `factory.db` (store migration V5): `id`, `kind`, `key`, `text`, `created_at`, `resolved_at` (empty while open). Code: `cf.research.notes`.

| Kind | Key |
|---|---|
| `document` | repo-relative path of a catalogued document, e.g. `.claude/skills/reel/SKILL.md` |
| `skill` | skill name, e.g. `write-script` |
| `video`, `card`, `idea` | the entity's id: the Video slug (`<walk>~<reel>` for a legacy Reel), the Reference's YouTube video id, the Idea id |
| `general` | empty: applies to every skill |

In Desk every document, Video page, Reference card and Idea has a Notes box under it (add, resolve, delete), and the Notes page (`#/notes`) lists all open Notes grouped by kind and takes general Notes. The Editor uses the CLI:

```sh
python -m cf.research notes list [--kind K] [--key PATH|ID] [--all] [--json]
python -m cf.research notes add <kind> <key> "<text>"     # "" as key for general
python -m cf.research notes resolve <id>
python -m cf.research notes delete <id>
```

### Skill hook

`.claude/settings.json` runs `.claude/hooks/skill_notes.py` (with `.venv/bin/python`) on `PreToolUse` for the `Skill` tool and on `UserPromptExpansion` (a typed `/skill` bypasses `PreToolUse`). It hands the Editor, as `additionalContext`, the open Notes of kind `skill` for that skill, of kind `document` under `.claude/skills/<skill>/`, and the `general` ones, with the command to resolve them. It reads `factory.db` read-only with the stdlib (same path rules as `cf.research`) and never migrates it; with no db, no `note` table, no matching Notes or unexpected input it prints nothing and exits 0. The rule in `CLAUDE.md` (Agent skills, Notes) covers the entity a skill works on, which the hook cannot know.

## Videos

Code: `src/cf/desk/videofolders.py` (which folders are Videos, `video.json` reading, the list summary), `src/cf/desk/videos_api.py`, `src/cf/desk/channels.py`, `src/cf/desk/media.py`, `web/src/videos/`. Desk lists every `videos/<slug>/video.json` in the footage root (ADR 0006) and every legacy `<walk>/reels/<reel>/`, addressed as `<walk>~<reel>`, with format `walk-reel` and a status derived from the folder: `script` when a Script `.json` exists, `edit` with `cuts.json` or overlays, `review` with a render in `out/`. Everything is read per request; nothing is cached.

`video.json` is `cf-video/1`: `slug`, `title_working`, `format`, `channel`, `language`, `walks`, `status`, `history[{status, at, note}]`, `references`, `ideas`, `published_url`. Statuses in order: `idea`, `brief`, `script`, `recording`, `edit`, `review`, `published`.

The sidebar shows each Video's status as one of four stages (`videos_api.stage_of`):

| `video.json` status | Stage |
|---|---|
| `idea`, `brief` | `idea` |
| `script`, `recording` | `script` |
| `edit`, `review` | `edit` |
| `published` | `done` |
| none, unknown, or `video.json` unreadable | `null` (hollow dot) |

**Creating a Video.** `POST /api/videos` makes `videos/<slug>/` and writes `video.json` (`status: idea`, one `history` entry dated today UTC, `walks: []`, `published_url: null`). With `idea_id` it first copies the Idea's Brief byte for byte to `brief.md` (a snapshot: later edits to the contour Brief do not flow into the Video; the Brief file itself is left untouched), sets `ideas: [<id>]` and `references` to the external ids of the Idea's sources, and records the Idea side of the link in `factory.db` (`idea_video`, schema version 7; `cf.research.ideas.link_video`), so the Idea lists the Video. A Brief that already has a Video can be used again; each Video gets its own row. `language` is the linked Idea's Watchlist language, else the one language shared by every Watchlist of that Channel, else null. `video.json` is written, then the link; on any error after the folder is claimed (a failed link write is 500 `idea_link_failed` with `id` and `detail`) the folder is removed, so a half-made Video is never listed. Nothing is started: no subprocess, no skill (ADR 0005).

The slug comes from the title: Russian and Ukrainian Cyrillic transliterated to Latin (`і`→`i`, `ї`→`yi`, `є`→`ye`, `ґ`→`g`, `ж`→`zh`, `х`→`kh`, `ц`→`ts`, `ч`→`ch`, `ш`→`sh`, `щ`→`shch`, `ю`→`yu`, `я`→`ya`, `ъ`/`ь` dropped, …), Latin accents dropped (`Zürich`→`zurich`, `Kraków`→`krakow`), lower case, every run of other characters turned into one `-`, cut to at most 60 characters at a `-`, and `video` when nothing is left. It is always ASCII, so the folder matches the Video name rule. The first free name of `<slug>`, `<slug>-2`, `<slug>-3`, … is claimed with an exclusive `mkdir` (correct on case-insensitive APFS, and a stray folder without `video.json` counts as taken).

**Channels.** There is no Channel registry. The known Channels are the union of the Watchlists' `author_channel` in `factory.db`, the Brief folders `<footage>/channels/<name>/` and the `channel` of every `video.json`; `_unassigned`, hidden names and names that are not folder names are left out. Without a readable `factory.db` (missing, or another schema version) the store part is skipped and the rest still counts. Creating a Video for an unknown Channel needs `new_channel: true` (the form's "New Channel…"): the name is trimmed and lower-cased, at most 64 characters, and when it equals a known Channel ignoring case the Video gets that Channel. Desk creates `videos/` under an existing footage root only; a missing root is 409 `footage_missing` and nothing is made.

| Endpoint | Returns |
|---|---|
| `GET /api/videos?format=&channel=` | `videos` (`slug`, `title`, `format`, `channel`, `status`, `stage`, `legacy`, `updated`, `error`), newest change first, `statuses` and `stages` (`idea`, `script`, `edit`, `done`); `format` and `channel` are exact filters combined with AND, an empty value means no filter and an unmatched one gives an empty list |
| `POST /api/videos` | body `{title, format, channel, new_channel?, idea_id?}`: creates the Video as above and returns 201 with the body of `GET /api/videos/{slug}`. Checked in this order, the first failure answers and nothing is written: 422 `request_invalid` (a missing or mistyped field), `title_empty`, `title_too_long` (`max` 200 after strip), `format_unknown` (not a `formats/<id>/FORMAT.md`; `formats` lists the known ids), `channel_invalid` (with `new_channel`, a name that is not a folder name, longer than `max` 64 or `_unassigned`), `channel_unknown` (without `new_channel`, not a known Channel; `channels` lists them); with `idea_id`, 404 `db_missing` / 409 `db_schema`, 404 `idea_not_found`, and the Brief errors of `GET /api/contour/ideas/{id}/brief` (`brief_missing`, `brief_outside`, `brief_file_missing`); last, 409 `footage_missing` when the footage root does not exist |
| `GET /api/channels` | `channels` sorted by `id`: `formats` (of its Watchlists and Videos), `languages` (of its Watchlists), `watchlists`, `videos` (count) |
| `GET /api/videos/{slug}` | `video` (the `video.json`, or the derived one for a legacy Reel), its `hash`, `statuses`, `files` (`path`, `kind`, `size`, `mtime`, `editable`, `media`) and the Walk `proxies` |
| `POST /api/videos/{slug}/status` | body `{status, note, hash}`: sets the status, appends `{status, at: today (UTC), note}` to `history` and rewrites `video.json`; 409 on a stale hash or for a legacy Reel, 422 for an unknown status |
| `GET /api/videos/{slug}/file?path=` | an editable text of the folder (a Script: a top-level `script.md|json`, or `script` then `.`, `-` or `_` then anything `.md|json` such as `script.v2.md` or `script-long.json`, not `scripting-notes.md`; `cf.assets.is_script_file`; `brief.md`, `voiceover.md`, `notes.md`, `references.md`, `.srt`/`.vtt`): `kind`, `format`, `text`, `hash` |
| `PUT /api/videos/{slug}/file` | body `{path, text, hash}`: the same hashed atomic write as documents; `brief.md`, `voiceover.md` and `notes.md` can be created with `hash: ""`; the hash is checked first (409 on a stale one, before any JSON check); a Script `.json` must be a `cf-script/1` document (a missing or other `schema` is a violation) and is validated by `cf.script_schema` (with the Walk's `clip_manifest.json` and the repo `style.json` when present); a Script with Asset cues (`shots[].assets`) is also checked against the Library (read-only from `factory.db`) and the refs in the Video folder's top-level md files (not the Scripts), which unlock Assets of unknown rights (with no readable db the cues fail with "need the Library"; a Script without cues opens no store); warnings (unknown rights allowed) are not returned; 422 with `violations` writes nothing |
| `GET /api/media?path=` | file streaming with HTTP Range (206) for paths relative to the footage root under `videos/<slug>/{renders,overlays,sources}/`, `<walk>/proxy/`, `<walk>/reels/<reel>/`, `references/<watchlist>/<id>/proxy.mp4`, and the Library namespaces `library/<pack>/…` and `packs/<pack>/…` (see Library); `raw/`, symlinks out, directories and everything else are 404 |

The web page lives at `#/videos` (list) and `#/videos/<slug>`, and `#/new-video` is the form behind "+ New video" (title, Format, Channel or "New Channel…", an optional Brief from the Ideas with status `brief`, which fills the empty fields; a Brief that already has Videos reads "… — already has video: <title>", stays selectable and, once picked, shows links to those Videos under the select; with no readable `factory.db` the Brief select is disabled and the rest still works); a Video page links its `video.json` `references` to their cards (`#/contour/cards/<id>`) and its `ideas` to the Idea inbox (`#/contour/ideas/<id>`). ProRes 4444 overlays play in Safari only.

## Research contour

Code: `src/cf/desk/contour_api.py`, `web/src/contour/`. The research contour (`GLOSSARY.md`, section Исследование) over `factory.db`: Watchlists, their feed, Reference cards, summaries, the Idea inbox with Briefs, the taxonomy and today's quota. Every endpoint calls `cf.research` modules directly (no subprocess, nothing on the network: scout, snapshot and fetch stay with the Editor) and opens a Store per request (read-only for reads, see above). An unknown Watchlist, Reference or Idea is 404; any other error the CLI reports as a user error (`USER_ERRORS` in `cf.research.cli`, plus a bad summary name) is 422 with the message, violations appended one per line.

## Library

Code: `src/cf/library/` (no Desk imports; CLI `python -m cf.library`, skill `/index-pack`), `src/cf/desk/library_api.py`, `web/src/library/`. ADR 0007, `GLOSSARY.md`: Library, Pack, Asset, Asset ref.

- **Packs** are registered in `factory.db` (`pack` table, schema version 6) from a `cf-pack/1` config (`.claude/skills/index-pack/packs/<id>.json`: `root`, `include`, `exclude`, `templates`, `folders` → `category`, `rights`, `key`, `group`). A Pack is read in place and never written.
- **Cache** `<footage root>/library/<pack>/`: `index.json` (`cf-library-index/1`), `keyed/<id>.mov` (ProRes 4444 alpha of green-screen folders), `converted/<id>.mov` (animated gifs), `png/<id>.png` (jfif, webp, avif stills), `previews/<id>.jpg` and `previews/<id>.mp4` (240 px), `sheets/NN.jpg` + `NN.json` (agent tag pass). Deleting it loses nothing the Author wrote.
- **Author fields** (`asset_author`: name, caption, tags, rights, `hidden_agent_tags` (schema version 7): agent tags the Author rejected; they match no tag filter or text search and leave cards and facets, while the index keeps the agent's proposal) and **aliases** (`asset_alias`: old refs after a rename, an Author rename or the face-sticker label import) live in the store, keyed by the Asset id (content id of the primary variant).
- **Refs** `@<category>/<name>`, categories `sfx meme img emoji face bg footage fx music font template`. Grammar (Python `cf.library.refs.REF_RE`, JS `web/src/library/refs.ts`): `@` at the start or after whitespace or one of `([«"'`, a category, `/`, letters, digits and `-`. A new category means editing both. Resolution: the Author's name, then the file-derived name, then an alias.

The Library is loaded per request; with no `factory.db` or one at another schema version there are no Packs and every Asset route is 404. Errors carry a `code` and `params` (`err.<code>` in the frontend).

| Endpoint | Returns |
|---|---|
| `GET /api/library` | `packs` (`id`, `root`, `indexed_at`, `index_missing`, `assets`, `by_category`, `fallback` folder count), `categories`, `rights` |
| `GET /api/library/assets?pack=&category=&tags=&q=&rights=&limit=&offset=` | `assets` (cards), `total`, `tags` (up to 50 facets `{tag, n, author}` over the filtered set, active and Author tags first); `tags` comma-separated and ANDed over Author and (not hidden) agent tags, Assets whose Author tags hit more of them first (the Author's tags weigh more than the agent's; `cf.library query --tag` ranks the same), then by category and ref; `q` a substring of ref, names, aliases, captions, tags and file name; default limit 200, max 5000; 422 `library_query_invalid` (`param`, `value`) |
| `GET /api/library/assets/{id}` | `asset` (card with `variants`); 404 `asset_not_found` |
| `PUT /api/library/assets/{id}/author` | body with any of `caption`, `tags`, `rights`, `name`, `hidden_agent_tags` (same rules as `tags`); only present fields change, `null` clears (`rights: null` = the Pack default); the card. 422 `rights_invalid`, `tags_invalid` (a list of strings, no commas, ≤ 40 characters), `caption_invalid`, `ref_name_invalid` (`name`, `slug`); 409 `ref_name_taken` (`ref`, `holder`, `holder_id`, `holder_file`) |
| `GET /api/library/refs/resolve?ref=` | `ref`, `canonical`, `alias`, `asset`; 422 `ref_invalid`; 404 `ref_not_found` with `suggestions` (up to 5 cards) |
| `POST /api/library/refs/check` | body `{refs}` (≤ 200): `refs` as `{ref: {ok: true, id, canonical} \| {ok: false, suggestions: [ref]}}` |
| `GET /api/library/refs/suggest?q=&limit=` | `suggestions`: refs starting with `q`, then names containing it, then Author and agent captions and tags |
| `GET /api/library/tags?q=&limit=` | `tags` with the prefix, Author tags first |
| `POST /api/library/assets/{id}/reveal` | runs `/usr/bin/open -R <file>` and returns `path`; 404 `asset_not_found`; 409 `reveal_unavailable` off macOS |

Card fields: `id`, `pack`, `category`, `category_source` (`mapping`, `fallback`, `kind`), `ref` (canonical), `name` (file-derived), `author_name`, `aliases`, `kind` (`audio`, `video`, `image`, `font`, `template`), `folder`, `file` (`path`, `name`, `size`, `mtime`), `media` (`original`, `alpha`, `png`, `poster`, `preview`: `path=` values for `/api/media`, null when not served), `duration_s`, `fps`, `width`, `height`, `has_audio`, `alpha`, `green_screen`, `loudness` (`i`, `tp`, `lra`, `method`), `rights`, `rights_default`, `rights_override`, `caption`, `tags`, `agent_caption`, `agent_tags` (without the hidden ones), `hidden_agent_tags`, `updated_at`.

Page (`web/src/library/`): `#/library` shows the Packs strip (Asset count, index time, or the `/index-pack` hint when the index is missing; with no Pack, the `pack add` command), category chips with counts, a search box (200 ms debounce), a rights select and tag facet chips (AND; agent tags dashed); the filter lives in the hash query (`#/library?category=face&tags=шок&q=…`), so a filtered view can be bookmarked. Tiles show the poster (a muted looping preview on hover for video), a play button for audio (one sound at a time), a sample line in the font for fonts, the file name and "Show in Finder" for templates, and the ref, duration and badges (alpha, green screen, rights, loudness). `#/library/<id>` opens the card drawer beside the grid (Esc closes): a large preview, facts, aliases, the rights select with the Pack default, and the Author's caption, tags (autocomplete from `/api/library/tags`) and ref name, each saved on blur or Enter; the agent's proposals sit muted under them with "use" and "+", and "×" on an agent tag hides it (`hidden_agent_tags`; the hidden ones are listed below with "↺" to bring one back). `#/library/ref/<ref>` resolves a ref and opens its card, or shows the 404 with suggestions.

Refs in Video texts: the markdown editor of a Video's `brief.md`, `voiceover.md` and `notes.md` (`CodeEditor` with `refs`, `web/src/library/cmRefs.ts`) completes `@` refs from `/api/library/refs/suggest` (at least one character after `@`; the info panel shows the poster, or an audio control for sounds, with caption and tags), underlines refs (a red wavy line for one that does not resolve, checked in batches through `/api/library/refs/check` 300 ms after typing stops; saving is never blocked), shows a card on hover with "Open in Library" (for a broken ref: up to 5 suggestions that replace it on click) and opens `#/library/<id>` on Cmd/Ctrl+click. Every markdown Preview renders refs as links to `#/library/ref/<ref>` (`web/src/library/marked.ts`).

Media: `library/<pack>/{previews,keyed,converted,png,sheets}/<file>` from the cache, and `packs/<pack id>/<path in the Pack>` from the registered root, only for files the Pack's index lists (so excluded or un-included folders such as `_каталог` are 404) and only for audio, video, image and font suffixes (no `..`, hidden part or symlink on the way; templates, text and everything else 404; with no readable db every `packs/` path is 404). `.jfif` is sent as `image/jpeg`, fonts as `font/ttf` and `font/otf`.

## Frontend

`web/` is Vite + React + TypeScript + CodeMirror 6.

The left sidebar (`web/src/shell/`) holds, top to bottom: "+ New video" and the search box; Tools (Research → `#/contour`, Formats, Library, Notes); the Videos, newest change first, each with its stage dot, filtered by Format and Channel through `GET /api/videos` (the choice is kept in `localStorage` `desk.videoFilter`); pinned at the bottom, Agent and the EN/RU switch. The current page is highlighted (`aria-current="page"`). The header holds only the breadcrumb, whose last item is the page title (a Video reads "<Format title> › <Video title>"). The Videos, Formats and Channels behind the sidebar and the breadcrumb are reloaded after a create or a status change, on every route change, when the window regains focus or becomes visible, and when the Videos table or the New video form opens, so files the Editor writes show up without a page reload.

`#/agent` is the Agent page: the catalogue (the groups above, the vendored toggle, lock, git and lint badges) on the left, and the repo path and branch, the footage root, the db path and a link to the research docs on the right; `#/doc/<path>` and `#/research*` open in the same layout. `#/library` is the Library page (see Library). The empty hash and unknown hashes show the Videos table.

Routes are hash routes: `#/doc/<path>` (document with Edit, Diff vs HEAD and History tabs; a skill's `SKILL.md` also shows what it mentions and who mentions it), `#/research` (topics with file flags, synthesis), `#/research/<NN-slug>` (`rules.md` with an editor, answers and notes in tabs with a contents list built from their headings), `#/search/<query>` (the sidebar search box). `npm --prefix web run dev` starts Vite on its own port and proxies `/api` to `127.0.0.1:8765` (run `python -m cf.desk` alongside). `npm --prefix web run lint` runs eslint and tsc. The Format shelf (`#/formats`, `#/formats/<id>`) and the skill lint badge and list live in `web/src/formats/`. `npm --prefix web run build` writes `web/dist`, which `cf.desk` serves at `/`. `web/node_modules` and `web/dist` are gitignored.

## Language

The UI speaks English (default) and Russian. The EN/RU switch at the bottom of the sidebar sets the language; the choice is kept in `localStorage` (`desk.lang`), and with no stored choice or no storage the UI is English. `<html lang>` and the page title follow it. Dates, numbers and sizes use `Intl` with `en-US` or `ru-RU`.

Code: `web/src/i18n/`. `en.ts` holds every key and is the source of the `Key` type; `ru.ts` is typed `Dict`, so a key missing in either file is a type error. Components call `const t = useT()` and then `t("key", { name })`, `t("key", { n })` for counts (an entry `{ one, few, many }`; Russian picks one/few/many, English one/many), `t.rich("key", { cmd: <Cmd>…</Cmd> })` when a placeholder is markup, `t.or(dynamicKey, fallback)` for keys built from data, and `t.problem(error)` for an API error (`err.<code>`, else its `detail`). To add a string: add the key to `en.ts`, then to `ru.ts` (`npm --prefix web run lint` names the missing one), and use it through `t`. Russian taxonomy labels live in `i18n/taxonomy.ts` (English uses the label from the store), CodeMirror's own phrases in `i18n/codemirror.ts`. File names, paths, commands, skill names, taxonomy values and document contents are never translated.
