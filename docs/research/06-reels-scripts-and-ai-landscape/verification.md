# Проверка result-a по локальному окружению

Дата: 2026-10-10.

## Проверено: Python 3.12 и модуль Resolve

Ресерч (пункт 1 секции E) предупреждает, что модуль `DaVinciResolveScript` использует `imp`, удалённый в Python 3.12, и советует держать venv на 3.11.

**Это устарело.** В модуле из Resolve 21.1.1 (`Developer/Scripting/Modules/DaVinciResolveScript.py`) загрузка идёт через `importlib.machinery.ExtensionFileLoader`, а `imp.load_dynamic` остался только как запасной путь для старых интерпретаторов. Прямой тест в нашем `.venv` (Python 3.12):

```
import DaVinciResolveScript  →  import OK
scriptapp('Resolve')         →  None   (Resolve не был запущен, ожидаемо)
```

Импорт работает. Отдельный venv на 3.11 не нужен. Подключение к живому Resolve проверим smoke-тестом, когда он будет открыт.

## Расхождения с другими ресерчами

- **Gyroflow для Osmo.** Ресерч 06 советует Gyroflow для Osmo-футажа («подтверди, что твой Pocket пишет гиро»). Ресерч 04 утверждает обратное: Osmo Pocket гиро-данные не отдаёт и в списке Gyroflow его нет. Пока считаем, что Gyroflow для Osmo не работает, проверим на реальном файле.
- **MCP или свой слой.** Ресерч 06 говорит «начни с samuelgursky MCP», ресерч 01 говорит «MCP только для исследования, продакшн через свой тонкий слой». На деле оба предлагают одно и то же: MCP как справочник, свой `resolve_driver.py` для сборки.
- **Публикация через Graph API.** Ресерч 06 считает её главным способом замкнуть цикл (хранить watch time и shares рядом со Script). В v1 публикация исключена по решению пользователя, но формат Script стоит сразу оставить место под метрики.
