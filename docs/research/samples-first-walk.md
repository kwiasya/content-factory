## Выводы

1. **Таблица детекта цвета из ресерча 03 подтверждается на реальных файлах.** iPhone HDR: `color_transfer=arib-std-b67` + DOVI profile 8 / compat 4, ровно как предсказано. iPhone SDR: `bt709` по всем трём полям, без DOVI. Osmo в этой прогулке нет, его профиль проверим на первом же файле.
2. **Два телефона, два профиля в одной прогулке.** Один клип SDR с другого iPhone среди 13 HDR. Это ровно тот микс, под который строится color-managed проект с тегом на клип. Ещё этот клип `yuvj420p` full range: при теге Input Color Space следить за data levels (video, не full).
3. **Основная съёмка 1080p60, не 4K.** Прокси 540p для анализа всё равно нужны (HEVC 10-bit HDR декодировать дорого), но итоговый 1080×1920 из 1080p-исходника без запаса на кроп. Два клипа 4K дают запас. Для Style profile: не планировать punch-in больше ~1.1× на 1080p клипах.
4. **fps смешанные: 60, 24, 30.** Таймлайн 30 fps (решение D3) конформит 60 как slow-mo или 1:1 через `RetimeProcess`, 24 fps клип получит frame blend или nearest. Запись в Script: поле `speed` на клип.
5. **Поворот через Display Matrix.** Все клипы записаны как 1920×1080 с матрицей поворота. ffmpeg при создании прокси применяет `autorotate` по умолчанию, Resolve читает матрицу сам. В `clip_manifest.json` хранить `rotation` явно.
6. **VFR.** `avg_frame_rate` у iPhone-клипов не целый (58950/983 и т.п.). При анализе по секундам брать время из PTS, не из номера кадра.
