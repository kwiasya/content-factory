# Общая папка по SMB: одна база, Reference и Library на двоих

Над Channel теперь работают два человека на двух Маках: автор (YouTube, Pack шаблонов Resolve) и Настя (Instagram, свои Pack мемов). До сих пор у каждого была своя `factory.db`, свои Reference и свой кэш Library; Watchlist, карточки, Note и поля Author расходились. Решили держать исследовательский контур и Library в одной общей папке, а Footage и Video каждый держит у себя. Общий корень (`CF_SHARED_ROOT`, по умолчанию `/Users/Shared/content-factory`) хранит `factory.db`, `references/`, кэш `library/`, сами Pack в `packs/`, `secrets.env` и `backups/`. Настоящая папка лежит на Маке автора в `/Users/madvil2/Shared/content-factory` на уже открытом SMB-ресурсе `Shared`; на обоих Маках `/Users/Shared/content-factory` это символическая ссылка на неё (у Насти через `/Volumes/Shared`), поэтому абсолютные пути в базе одинаковы. Локальный корень (`CF_LOCAL_ROOT`, по умолчанию `~/Movies/content-factory`) хранит Footage, `videos/`, `channels/` (с Brief) и `_models/`. Настя подключается как пользователь только для общего доступа `nastaglusenko`; права обоим дают наследуемые ACL на папке.

## База на сетевом диске

- SQLite-файл с журналом `delete`: WAL по SMB не работает, `open_store` отказывается открыть базу в WAL. Каждое соединение ждёт блокировку 10 с; занятую дольше базу CLI называет занятой, Desk отвечает 503 `db_busy`.
- Базу создаёт только `python -m cf.research db init`. Никакая команда не создаёт `factory.db` по пути по умолчанию: при неподключённом ресурсе символическая ссылка висит, и команда завершается с подсказкой подключить `smb://<author-mac>.local/Shared`, ничего не создав локально.
- Мигрирует только CLI (`cf.research`, `cf.library`, `db migrate`) под `BEGIN IMMEDIATE`, сначала сделав копию `pre-v<N>`. Desk базу не создаёт и не мигрирует: на другую версию отвечает 409, на отсутствие 404. Чтение не пишет: сид таксономии сначала читает, Desk и хук открывают `mode=ro`.
- Копии в `backups/` рядом с базой: `daily` при первой команде дня после `quick_check`, `pre-<команда>` перед массовыми командами (scout, snapshot, fetch, own sync, index, pack remove), `pre-v<N>`, `pre-renumber`, `manual`. `db check` показывает путь, версию, журнал, `quick_check` и последние копии.

## Строки про локальные вещи

Строка базы, которая называет файл под чьим-то локальным корнем, хранит владельца (`CF_PERSON`, по умолчанию имя пользователя macOS): Brief Idea (`idea.brief_owner`), Note к Video (`note.owner`), связь Idea и Video (`idea_video.owner`); пустой владелец значит «автора, до общей базы». Чужие строки Desk и CLI показывают текстом с именем владельца и не открывают их файлы. Остальное в базе общее. Миграция store V10.

## Ключи

`secrets.env` в общей папке: ключ YouTube Data API автора и токен, приложение и аккаунт Instagram Насти, один файл на двоих; личный `.env` в репо хранит только `CF_PERSON` и корни. Квоты `quota` и `rate` уже считают один проект Google и один токен Meta, то есть ровно то, что тратят двое с общими ключами; отдельные счётчики на ключ не нужны. `ig token-refresh` переписывает строку в том файле, откуда взят токен.

## Слияние двух баз

Базы автора и Насти сливаются один раз командой `db merge` в новый файл, входы только читаются; `db renumber` чинит базу, которую старая ветка пронумеровала по-своему (Library как V6). Обе команды остаются в репо: проверка отчёта (числа строк, внешние ключи, целостность, карточки байт в байт, sha256 входов) нужна и при повторе.

## Отвергнуто

- WAL: требует общей памяти между процессами одного хоста, по SMB портит базу.
- Относительные пути в базе: путь к Reference и Pack пришлось бы собирать в каждом читателе; символическая ссылка даёт одинаковый абсолютный путь дешевле.
- Сетевое хранилище (база за HTTP у Desk автора) сейчас: больше кода, а двоим людям с несколькими записями в день хватает файла. Все обращения к базе идут через `open_store`, `storeuse`, `library/readonly` и хук, а к общим файлам через `shared_root()`, так что замена остаётся возможной.
- Две синхронизируемые копии базы: два источника правды и конфликты на каждой записи.
- Отдельная квота на каждый ключ: ключи общие, второй проект Google или приложение Meta появятся новым решением.

## Consequences

- Остаётся риск SMB: macOS переводит блокировки клиентов и ломает аренду при втором открытии, но локальные процессы автора и процессы Насти по SMB блокируют один файл разными путями, и этот смешанный случай никто не гарантирует. Ответ на этом масштабе (двое, 45 МБ, несколько записей в день): копии, `quick_check` перед ежедневной копией, восстановление копии, пока никто ничего не запускает. Если повреждения появятся, следующий шаг это сетевое хранилище.
- Без подключённого ресурса Desk запускается: Videos, Formats и документы работают, Library, контур и Note показывают подсказку подключить ресурс.
- Гостевой доступ к `Shared` выключается, как только работает `nastaglusenko`: иначе любой в сети читает `secrets.env`.
- `channels/` остаётся локальным, поэтому Brief видит только тот, кто его написал.
- Настройка, восстановление и порядок переезда: `docs/shared-setup.md`.
- ADR 0003 (путь Reference), 0005 (второй пользователь) и 0007 (путь кэша) в этих пунктах заменены этим ADR.
