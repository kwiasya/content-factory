# Instagram через Graph API Business Discovery

Channel автора живёт в Instagram, и большая часть Reference channel для Walk Reel тоже: многие нужные аккаунты есть только там (`docs/research/niche-seeds-2026-10.md`). Исследовательский контур до сих пор видел только YouTube. Решили сделать Instagram вторым источником через официальный Instagram Graph API (v25.0, graph.facebook.com) от имени бизнес-аккаунта автора: Business Discovery даёт чужой бизнес- или креатор-аккаунт (подписчики, число публикаций) и страницы его медиа по 50 с `view_count`, лайками, комментариями, подписью, датой и permalink; свой аккаунт отдаёт свои Reels с insights (охват, просмотры, сохранения, репосты, взаимодействия, среднее и общее время просмотра) одним вызовом на страницу. Причины: это официально и бесплатно, данные те же, что видит автор, а D1 и D2 из ADR 0003 держатся: статистика из API в нашей `factory.db`, своя история снимков по дням, Outlier score по тому же правилу, что на YouTube (просмотры против медианы своих Reels аккаунта; где `view_count` нет, по лайкам).

Альтернативы отвергнуты: скрейпинг instagram.com и неофициальные клиенты (instaloader и подобные) требуют входа или куки, ломаются от каждого изменения сайта и рискуют аккаунтом автора; платные API (Apify, RapidAPI-обёртки, Sandcastles) стоят денег за каждый запрос, тянут тот же скрейпинг за чужим фасадом и не видят insights своего аккаунта.

## Consequences

- Видны только публичные бизнес- и креатор-аккаунты. Личный или закрытый аккаунт Business Discovery не находит: `watchlist add-channel` сообщает об этом одной строкой, scout продолжает остальные.
- Ни видео, ни транскрипта API не даёт. `fetch` пробует yt-dlp без входа и без куки; если Instagram отказывает, карточка остаётся caption-only с пометкой в `measured.notes.media`. Куки и логин не используются никогда.
- Найти чужой Reel по ссылке Business Discovery не умеет: владелец берётся из метаданных yt-dlp (вежливо, с паузой, до первых отказов подряд), иначе из уже прочитанных медиа аккаунтов Watchlist, иначе ссылка хранится неразрешённой (ссылка и Note автора, без владельца и цифр).
- Лимит около 200 вызовов в час на пользователя. Отдельная часовая корзина `instagram` в `quota` (скользящие 60 минут, по умолчанию 100 вызовов: на живом аккаунте заголовок Meta показал 51 % после 62 вызовов, `CF_QUOTA_INSTAGRAM`) планируется до старта как корзины YouTube; заголовки `X-Business-Use-Case-Usage` и `X-App-Usage` пишутся в базу, и от 90 % корзина встаёт на паузу. Ошибка лимита от Meta ставит паузу на час.
- Поиска по запросам в Instagram нет: поисковые запросы Watchlist остаются только YouTube.
- Длительность Reel API не отдаёт: Reel Instagram всегда `short`, фильтр `--max-duration` их отбрасывает до `fetch`.
- Нужен долгоживущий токен пользователя Facebook (60 дней) и Meta-приложение: `ig token-status` показывает срок, `ig token-refresh` обменивает токен и переписывает одну строку `.env`; scout предупреждает, когда остаётся меньше 7 дней. Токен никогда не печатается и уходит только в заголовке `Authorization`.
- Reference в Instagram идентифицируется shortcode из permalink (`instagram.com/reel/<shortcode>/`), а не Graph id медиа: так совпадают данные из API, из yt-dlp и из вставленной автором ссылки.
